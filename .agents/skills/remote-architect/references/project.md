# Remote project contract

- Use the primary checkout and the fixed toolchain declared in the workspace manifest. Synapse is the reference for explicit package composition, reproducible verification and maintainable documentation.
- Follow Mosaik's Nx task layout under `infra/nx-tasks`. Register each executor in `executors.json` and keep its schema, typed options and implementation together under `src/executors/<capability>`.
- Keep protocol/core/client independent of browser globals, UI frameworks, Electron APIs and product models. Node, browser, Angular, Electron and Capacitor adapters compose these same owners.
- Applications own identity namespaces, business authorization, immutable asset roots, storage locations and certificate supply. Pairing grants only registered capabilities. Core owns challenge expiry, one-time use, durable device grants, typed errors and immediate revocation.
- Preserve public behavior across entry points. Verify pairing recovery, app/host isolation, disposal, host replacement, stream cancellation, bounded backpressure and non-replay of writes. Run browser, Electron and native verification for their actual adapters.
- Authored contracts live under `.docs/`. Follow the [implementation plan](../../../../.docs/plan.md) and record substantive changes there.
- Use Synapse’s per-package `src/index.ts` and `tsconfig.lib.json` layout. Group contracts, models and implementation by responsibility. Keep package entry points explicit and follow Archipel’s region order in classes.
- Apply the owner's lowercase folder convention to every TypeScript responsibility directory. Place each interface in its feature's `interfaces/` and each abstract class in `abstracts/`, including nested and internal declarations. Preserve required native platform directories. Public filenames match their declarations; pure entry-point barrels and Nx's required `executor.ts` follow their actual tool contracts.
- Apply the complete source documentation contract: multiline English TSDoc, separate access tags, documented interface members and accurate parameter, return, failure and lifecycle behavior. A one-line declaration summary does not satisfy the API documentation gate. Verify generated TypeDoc coverage and inspect the resulting reference.
- Follow the [API documentation guide](../../../../.docs/guides/api-documentation.md) for English TSDoc, regions and generated references. Run `yarn docs` when an SDK declaration or TSDoc changes and verify it with `yarn docs:check`.
- Keep unit and integration tests in colocated TypeScript `.spec.ts` files with Vitest. Use TypeScript Playwright specs for browser and Electron behavior. Follow the [testing guide](../../../../.docs/guides/testing.md) and update it when runner or test ownership changes.
