# @pixel-brewery/remote-capacitor

Capacitor8.6.2 native in-app Remote client for Android24+ and iOS15+. The packaged web application runs through an authenticated loopback content gateway. Remote host scripts never execute with a privileged native bridge. HTTP LAN is supported without domains or certificate installation; HTTPS retains platform trust validation.

In web code call `createCapacitorRemoteBridge()` to obtain frozen list/pair/open/close/forget and native QR-scan operations. The plugin accepts only canonical `IRemoteNativeRequest` payloads and validates every response against the shared Zod-derived protocol. It exposes no arbitrary HTTP proxy, credential getter, route configuration or content-directory setting. QR material is temporary and is not a session credential.

Android: install `RemoteNativeConfiguration` from the native Application with immutable product appId, private storage, copied packaged assets and exact registered routes. Extend `RemoteBridgeActivity`; it recreates the trusted Capacitor bridge with the protected loopback origin before content loads and disables mixed content, arbitrary navigation, file access and third-party cookies. Apply the provided `remote_network_security.xml` in the application manifest: all WebView cleartext remains denied except loopback. Native Ktor CIO performs scoped private-peer networking separately. Call the application-owned configuration's explicit `dispose()` when its native remote owner exits. Android Keystore AES-GCM protects credentials; the bundled MLKit17.3.0 scanner works without a model-download dependency.

The Android view capability is a persistent `remote_local` cookie with a bounded `Max-Age`, flushed before the bridge is recreated, because Capacitor's `CapacitorCookies` plugin removes session cookies on every bridge load; it is refreshed while the view is active and expired on close, forget, replacement and `dispose()`. iOS keeps a session cookie, which survives bridge recreation, and removes it on close, forget and `dispose()`. See [native view capability](../../.docs/packages/remote-capacitor/README.md).

iOS: install and retain `RemoteNativeHost` during native application launch. Supply `RemoteNativeConfiguration` and an activation callback that recreates `RemoteBridgeViewController`. The host installs its HttpOnly local cookie before that callback. Add the camera/local-network purpose descriptions and narrow numeric-private-network ATS policy shown by the mobile fixture; do not enable global arbitrary loads or arbitrary WebView content loads. SwiftNIO/NIOTransportServices owns the loopback listener; URLSession streams selected-peer requests and WebSockets without redirects. Keychain stores installation-local records and AVFoundation supplies QR scanning. The application owns host disposal and bridge recreation.

SwiftPM exports both `RemoteCapacitor` and the Capacitor-CLI-compatible product alias `PixelBreweryRemoteCapacitor` from the same `RemoteCapacitor` target. The generated `cap sync ios` package can use its regular npm-derived product name; Swift source continues to `import RemoteCapacitor`.

Native resource JSON is generated from the canonical protocol and shared conformance vectors; no second handwritten wire model exists. Native validators additionally enforce origin-only addressing, selected endpoints, matching session identities and trimming semantics. Peer selection rejects public, loopback, ambiguous or DNS names; route selection denies unregistered methods and ambiguous parameter matches. Byte streams preserve SSE, WebSockets, media Range and cancellation without write replay.

Native `RemoteNativeConfiguration.contentPolicy` is an immutable boolean map validated against the generated `remoteContentPolicy` schema. Its optional `allowHttpsImages`, `allowHttpsMedia` and `allowHttpsConnections` flags default to false. An application can explicitly permit those HTTPS resources in trusted packaged content without extending native proxy routes, scripts, frames or navigation. Unknown keys fail validation.

Each native route's streaming request quota defaults to1MiB and can be configured up to64MiB. This limit counts the original multipart/request stream incrementally; it never allocates a body buffer of that size. The iOS bridge retains its separate256KiB queue bound, and the browser's generic byte-port buffer has an independent8MiB default. Applications retain their own file-purpose and multipart limits.

`yarn nx run remote-capacitor:build`, `:typecheck` and `:test` check TypeScript. `:android-compile` builds the AAR and runs canonical JVM tests with Gradle9.6.0/JDK21/API36/BuildTools36.0.0. CI can use regular `gradle`; set `GRADLE_BIN` only for a local wrapper. `:ios-compile` builds the Swift package for an iOS Simulator using Xcode; `:ios-test` selects an available iOS Simulator automatically, or accepts `REMOTE_IOS_DESTINATION=platform=iOS Simulator,id=<device-id>`. Its XCTest cases cover shared conformance vectors, the HTTP loopback cookie and its removal on close, and bounded upload cancellation. Native build, simulator tests, camera permission and real LAN-device journeys are distinct verification claims.

iOS builds require Xcode26+ for Capacitor8. CI selects Xcode26.3/Swift6.2 explicitly on the supported macOS15 ARM64 image; its default Xcode must not be used. SDK compilation, every simulator test and both fixture app builds remain mandatory.

Android uses AGP9.5.3 built-in Kotlin; the explicit KGP2.4.21 buildscript classpath selects its compiler version without applying `org.jetbrains.kotlin.android`. A consuming source project must align its Android toolchain with the AGP9 library. The tested source-consumer configuration is AGP9.5.3/Gradle9.6.0/JDK21/API36/BuildTools36.0.0; the Android24 minimum is unchanged. Capacitor8.6.2 remains pinned: the actual AAR, seven JVM tests and both Counter/Notes APKs passed on 2026-11-26 with its unchanged AGP8.13.0 buildscript included. No Capacitor-major upgrade, vendor patch or built-in-Kotlin opt-out was needed. These compilation results do not establish device-runtime behavior. See the [platform verification contract](../../.docs/guides/testing.md#reproduce-the-platform-checks).
